本项目为**四足仿生机器狗动力与供电总控板（Power Management Board, PMB）**嵌入式核心固件。微控制器采用高主频电机控制与数模混合处理器 **STM32G474RBT6**（ARM® Cortex®-M4 @ 170MHz）。

本分支专为**单动力电池高可靠供电架构**深度适配定制，在全面支持 **V1.3 新版硬件**的基础上，彻底隔离电池 2 硬件回路以根除双电池跨组环流与倒灌风险，确立了**“放电态本地永不断电”**的机器狗高安全性供电哲学，集成了 **TIM8 互补 PWM 斩波反电势泄放**、**多路隔离 DCDC 动力时序**、**双路 FDCAN 协议网关**，并原生支持上位机**“供电无感热接力”CAN IAP 在线升级**。

## 一、核心功能特性

1. **单电池极简高可靠架构**：
   - 固件固化单动力电池专线供电逻辑，电池 2 物理引脚（PC10/PC11/PC12）强制常闭拉低，小脑遥测报文固定上报电池 2 已拔出（`0x02`），彻底消除双电池压差并网判定不确定性与环流风险。
2. **软启动预放电（Soft-Start Pre-Discharge）**：
   - 上电时先经由 400ms 预放电限流电阻回路缓冲，平稳充注母线大电容，随后闭合电池 1 主放电与回充 MOS 并维持 200ms 无缝重叠导通后断开预充 MOS，彻底消除直接闭合大电流 MOS 造成的打火与浪涌损坏。
3. **“放电态本地永不断电”安全哲学**：
   - 针对机器狗在奔跑、跳跃等大电流工况下的严苛安全要求，状态机一旦成功进入放电态（`POWER_BATTERY_STATE_DISCHARGE`），**本地放电 MOS 绝不因瞬态通信超时或未知状态主动切断**；
   - 通信掉线时仅通过 CAN2 向小脑上报 `0x01` 告警，由小脑受控执行阻尼缓降趴下，从底层杜绝空中粗暴断电摔狗致残。
4. **TIM8 高级定时器互补 PWM 斩波反电势泄放**：
   - 应对四足机器人落地冲击与紧急制动产生的反向高压泵升，采用高级定时器 TIM8 互补 PWM（`PC7` TIM8_CH2 与 `PB0` TIM8_CH2N，50% 占空比交替斩波）驱动双泄放回路，标准设计为母线电压超 85V 开启、跌落至 84V 关闭（1V 滞回防抖），均摊热负荷。
5. **小脑供电无感热接力 (Warm Handover)**：
   - 板载 12V / 24V 隔离 DCDC（小脑 RK3588 依赖 12V，三色灯面板依赖 24V）；
   - 支持基于 CAN 总线的免拆机在线固件升级，升级过程中全程保持动力 MOS 与 DCDC 导通，上位机小脑**不断电、不重启**。
6. **声光指示分层解耦**：
   - **板载 3.3V 独立指示灯**：`LED2` (PB1) 作为系统运行与 Bus-Off 心跳指示，`LED3` (PB2) 作为动力输出就绪/预充/泄放指示，直接由 MCU 供电驱动，自检过程无需依赖 24V DCDC；
   - **外部声光报警**：红/绿/黄 (PC15/PC2/PC14) 三色灯与 PC13 蜂鸣器完全开放给小脑通过 CAN2 功能码精准控制。
7. **充电模式与桩交互安全旁路**：
   - 单电池版本适配机器狗离线换电/直充方案，固件彻底关闭 FDCAN3 并旁路硬件充电 MOS 与充电桩握手逻辑，规避偶发总线异常。
8. **母线异常断开快速切断与防硬短路二次预充保护**：
   - 针对运行或待机中快速开关电池、接触不良瞬间合闸工况，放电态实时监测母线电压（$V_{BUS} < 30\text{V}$ 持续 10ms 或消抖期异常回弹），立即坚决切断全部功率 MOS、DCDC 与外设供电；
   - 退回 OFF 态后严格等待 BMS 重新通信握手且允许放电，才重新启动 400ms 预充软启动，彻底根除大电容高压差硬短路与电池 BMS 短路锁死故障。

## 二、硬件规格与系统拓扑 (V1.3)

### 2.1 硬件主要参数

- **微控制器 (MCU)**：STM32G474RBT6（LQFP64，最高 170MHz 主频，128KB Flash，128KB SRAM）
- **时钟源**：外部高速晶振 24MHz (HSE)
- **硬件版本**：V1.3（对应原理图 `v1.3_电源板原理图_2026-10-12.pdf`）
- **通信接口**：2 路活跃 FDCAN (250kbps)、1 路 RS485 (115200bps)、FDCAN3 硬件关闭
- **动力控制**：电池 1 功率 MOS（PB6 主放电 / PB9 预放电 / PB7 回充）+ 2 路 TIM8 互补斩波吸收 MOS
- **辅助电源**：12V 隔离 DCDC（PA7，低电平使能）、24V 隔离 DCDC（PC4，低电平使能）、外设电源 MOS（PA5，高开）

## 三、核心控制逻辑与安全哲学

### 3.1 软启动预放电控制 (400ms + 200ms 重叠)

当电池初次插入或系统冷启动时，主母线大电容电压为 0V。若直接导通大功率放电 MOS，极大的 $dU/dt$ 将产生数百安培的浪涌电流打火损坏器件：
1. **预充启动**：系统上电冷启动时，首先打开外设供电 MOS（`PA5`）与电池 1 预充 MOS（`PB9`）；
2. **限流缓冲（400ms）**：限流电阻平缓向母线电容充电 400ms（`POWER_PRE_DISCHARGE_DELAY_MS`），VBUS 逐步平滑抬升至接近电池电压；
3. **主回路接力与 DCDC 导通**：400ms 届满后，立即闭合电池 1 主放电 MOS（`PB6`）与回充 MOS（`PB7`），并拉低 `PA7`、`PC4` 使能 12V 与 24V DCDC 为上位机小脑供电；
4. **无缝重叠导通缓冲（200ms）**：主放电 MOS 导通后，预充 MOS 延时 200ms（`POWER_PRE_DISCHARGE_OVERLAP_MS`）断开，实现主备无缝重叠导通，彻底消除切换毛刺；
5. **进入就绪放电态**：板载 `LED3` 切换为常亮，蜂鸣器发出 90ms 短“滴”声提示动力就绪。

### 3.2 机器狗供电安全哲学与母线异常断电保护

四足仿生机器狗对供电连续性与电气安全具有极致的双重要求：
1. **正常工况与丢包保护（放电态本地永不断电）**：
   - 机器狗大电流跳跃、腾空与剧烈制动时容易产生电磁波动或瞬态通信丢包。一旦电池 1 经过预充进入放电状态（`battery1Control.state == POWER_BATTERY_STATE_DISCHARGE`），**固件绝不因瞬态通信超时或未知状态主动切断动力 MOS**；
   - 通信掉线超过 2000ms（`POWER_BATTERY_CAN_TIMEOUT_MS`）时，本地放电回路持续稳定供电，通过 FDCAN2 遥测帧（`0x04400000`）上报 `0x01`（`BATTERY_ALARM_STATUS_CAN_COMM_LOST`），由上位机小脑受控执行阻尼缓降趴下，杜绝空中粗暴断电摔机。
2. **极端失电与接触不良防硬短路保护**：
   - 当检测到母线电压跌破 **30.0V**（`POWER_VBUS_UNDER_VOLTAGE_THRESHOLD`，脱离正常工作电压区间）持续 10ms，判定为电池物理断开或关机，立即调用 `Power_TriggerAbnormalDisconnect()` 切断全部功率 MOS、DCDC 与外设供电；
   - **消抖期反弹闭环**：通过 `vbusLowVoltageDetected` 标志位锁存欠压历史。若在消抖期内母线电压快速回弹（如电池开关接触不良快速通断），坚决执行强制关断，杜绝主 MOS 导通状态下 80V 高压硬合闸冲入低压母线电容；
3. **断开恢复的严格二次预充准入**：
   - 异常断开后系统退回 `POWER_BATTERY_STATE_OFF` 并标记 `battery1AbnormalDisconnected = 1`；
   - 电池重新上电后，**严格等待 BMS 重新建立 CAN 通信且允许放电**（`CanAlive && BmsAllowed`），才重新启动 400ms 预放电软启动流程，主放电 MOS 闭合后才开通 12V/24V DCDC，从底层根除大电流浪涌与 BMS 短路锁死故障。

### 3.3 TIM8 互补 PWM 电机反电势吸收泄放

机器狗腾空落地反拖电机与急停时，机械动能回馈转化为电能灌入主母线 VBUS：
* **动作阈值与滞回防抖**：标准设计规范下，ADC2 连续检测 VBUS 电压，当母线电压上升超过 **85.0V** 时自动开启泄放；回落至 **84.0V** 时关闭（1.0V 滞回防震荡）；
* **互补斩波驱动**：启用 STM32 高级定时器 TIM8，通过 `PC7` (TIM8_CH2) 和 `PB0` (TIM8_CH2N) 输出频率 10kHz、占空比 50% 的互补 PWM 波形，交替导通泄放 MOS Q27 与 Q7，均摊功率发热；
* **声光告警**：泄放激活期间，外部蜂鸣器强制硬件报警长鸣，板载 `LED3` 以 50ms 周期高频爆闪；
* **台架与测试模式说明**：阈值由 [Core/Inc/gpio.h](file:///home/yq/ghf/workspace/D-Y/Core/Inc/gpio.h) 中的 `POWER_VBUS_RELEASE_OPEN_VOLTAGE` 和 `POWER_VBUS_RELEASE_CLOSE_VOLTAGE` 宏控制。在实验室台架上使用高压稳压电源调试时，可将阈值临时上调至 `999.0f` 并将占空比置 `0` 以旁路泄放回路。

### 3.4 状态指示灯与蜂鸣器 Alarm 告警控制

- **板载 3.3V 独立指示灯**：
  - **LED2 (PB1, 绿色)**：系统心跳。正常运行以 1Hz 慢闪（500ms 翻转）；若存在 FDCAN1/2 Bus-Off 或电池 1 异常时以 5Hz 快闪（100ms 翻转）；
  - **LED3 (PB2, 绿色)**：动力状态。预放电软启动期间 2Hz 闪烁（250ms 翻转）；动力输出就绪（放电 MOS 导通且 24V DCDC 开启）常亮；母线泄放激活时 50ms 爆闪。
- **蜂鸣器 Alarm 硬件告警决策优先级（PC13）**：
  1. **最高优先级（硬件过压泄放）**：母线反电势吸收泄放激活（`VBUS >= 85V`），强制蜂鸣器长鸣报警；
  2. **第二优先级（本地底层安全故障）**：发生**电池掉线/异常**（`battery1AlarmStatus != NORMAL`，含通信超时、BMS 禁放与未知状态）或 **FDCAN1/2 Bus-Off**，强制启动 Alarm 报警器（硬件间歇自激鸣叫），小脑指令无法静音覆盖；故障自愈后自动停止报警；上电初始具备 2000ms 宽限期（`POWER_BATTERY_BOOT_GRACE_PERIOD_MS`）等待 BMS 首包，避免开机瞬态误报；
  3. **第三优先级（小脑接管控制）**：小脑通过 FDCAN2（`0x04600000` Byte1）控制报警器开启/关闭；
  4. **第四优先级（本地开机就绪提示）**：放电回路导通就绪后单次短鸣 90ms（`POWER_BOOT_BEEP_DURATION_MS`）。
- **外部三色指示灯（红/绿/黄）**：
  外部指示灯正极受控于 24V DCDC，保持与小脑指令协议解耦，完全由上位机小脑通过 FDCAN2（ID: `0x04600000`）下发功能码（P0~P6 及各常亮态）直接驱动，单片机本地安全告警仅驱动板载 LED2 与 PC13 蜂鸣器。

### 3.5 充电模式与充电桩交互旁路说明

单电池版本针对目前四足狗的离线物理换电与离线直充方案进行了针对性精简与旁路：
1. **FDCAN3 硬件关闭**：原对接充电桩广播与电池 2 的 FDCAN3 外设彻底停用，消除空闲总线无 ACK 产生的连续重传与 Bus-Off 隐患；
2. **充电控制逻辑旁路**：`Power_EnterChargeMode()` 与 `Power_ExitChargeMode()` 直接返回 `HAL_OK` 空实现，硬件充电 MOS（`PB10`）保持常闭；
3. **小脑指令兼容**：小脑若下发 `0x04500000` 充电模式请求帧，单片机直接 ACK 并保持放电供电状态，避免误操作引发母线失电。

## 四、通信架构与小脑通信协议

### 4.1 FDCAN 通信职责划分

| 控制器 | 物理引脚 | 波特率 | 接入对象 | 职责与状态 |
| :--- | :--- | :---: | :--- | :--- |
| **FDCAN1** | PA11 (RX) / PA12 (TX) | 250 kbps | **动力电池 1 BMS** | 2s 周期广播唤醒帧 (`0x0400FF80`)，解析电芯参数、MOS 状态并透传转发至小脑 |

| **FDCAN3** | PA8 (RX) / PB4 (TX) | - | *(停用)* | **硬件彻底关闭**（不配置中断、不启动时钟与外设，根除无 ACK 隐患） |

| **`0x04600001`** | TX → 小脑 | 2 字节 | 500ms 周期 / 跳变即时 | **三色灯当前生效功能码与蜂鸣器 Alarm 状态回传** |

| **`0x040Exx01`** | TX → 小脑 | 8 字节 | 接收 BMS 立即转发 | **电池 1 故障与硬件告警码** |
| **`0x0407xx01`** | TX → 小脑 | 8 字节 | 接收 BMS 立即转发 | **电池 1 电芯各测温点温度遥测** |
| **`0x04600000`** | RX ← 小脑 | 1~3 字节 | 事件驱动 / 周期 | **小脑声光指示控制**（Byte0: 功能码, Byte1: Alarm, Byte2: 超时时间） |
| **`0x04700000`** | RX ← 小脑 | 1~8 字节 | 事件驱动 (上位机升级) | **CAN IAP 在线升级触发指令**（0x01 查询 / 0x02 切入 Bootloader） |

| *`0x040xxx02`* | - | - | *(已停用)* | *原电池 2 BMS 透传报文（单电池版本未挂载电池 2，不转发）* |

### 4.3 核心协议帧详细格式说明

#### 1. 电池告警与 MOS 状态遥测帧 (`0x04400000`)
- **发送频率**：100ms 周期广播，若 MOS 状态或报警发生跳变立即触发发送；
- **单电池适配字段映射**：
  - **Byte 0**：电池 1 告警状态：
    - `0x00`: 正常在线 (`BATTERY_ALARM_STATUS_NORMAL`)；
    - `0x01`: CAN 通信掉线 (`BATTERY_ALARM_STATUS_CAN_COMM_LOST`，本地仍保持放电供电)；
    - `0x03`: BMS 禁止放电 (`BATTERY_ALARM_STATUS_BMS_PROHIBIT_DISCHARGE`)；
    - `0x04`: BMS 状态未知 (`BATTERY_ALARM_STATUS_BMS_STATE_UNKNOWN`)。
  - **Byte 1**：**固定填 `0x02`**（`BATTERY_ALARM_STATUS_REMOVED`，明确告知小脑单电池硬件配置中电池 2 拔出/不存在）；
  - **Byte 2**：电池 1 主放电 MOS 状态（`1` 导通 / `0` 关断）；
  - **Byte 3**：电池 1 回充 MOS 状态（`1` 导通 / `0` 关断）；
  - **Byte 4~7**：预留固定填 `0x00`（电池 2 相关 MOS 恒为 0）。

#### 2. 外设放电电流与母线遥测帧 (`0x04200000`)
- **发送频率**：200ms 周期；
- **Byte 0~1**：外设总放电电流，单位 `0.01A`（有符号 16 位整型 `int16_t`，小端模式），经 ADC2 运放真实采样并低通滤波；
- **Byte 2~3**：系统动力母线 VBUS 电压，单位 `0.01V`（无符号 16 位整型 `uint16_t`，小端模式，范围 0~655.35V），经 ADC2 分压中值滤波采样；
- **Byte 4**：TIM8 互补斩波反电势泄放状态（无符号 8 位整型 `uint8_t`，`0x00`: 未泄放，`0x01`: 正在泄放中）；
- **Byte 5~7**：预留填 `0x00`。

#### 3. 小脑三色声光控制接口（`0x04600000` 控制 / `0x04600001` 反馈）
- **控制指令 (`0x04600000`)**：
  - **Byte 0**：功能模式码（`0x00`~`0x09`，对应常灭、开机绿灯、待机呼吸、正常慢闪、快闪告警等）；
  - **Byte 1**：蜂鸣器 Alarm 控制（`0x00` 关 / `0x01` 开 / `0xFF` 保持原状态）；
  - **Byte 2**：安全超时时间（单位 100ms，`0x00` 缺省 2s 超时，`0xFF` 常驻模式）；
- **状态回传 (`0x04600001`)**：2 字节，Byte 0 为当前生效功能码，Byte 1 为当前蜂鸣器输出电平。详细时序请查阅 [三色灯控制逻辑与CAN通信协议.md](file:///home/yq/ghf/workspace/D-Y/三色灯控制逻辑与CAN通信协议.md)。

#### 4. IAP 升级握手帧（`0x04700000` 指令 / `0x04700001` 回复）
- **PING 查询 (`0x01`)**：上位机下发 Byte 0 = `0x01`；MCU 回复 `0x04700001`，上报当前处于 App 态及版本号 `v1.4.1`；
- **切入 Bootloader (`0x02`)**：上位机下发 Byte 0 = `0x02`；MCU 校验后回复 ACK，并保持动力供电平滑跳转至 Bootloader。

### 4.4 FDCAN1/2 异步 Bus-Off 自愈机制

为防止总线受到动力大电流电机启动或剧烈刹车时的电磁脉冲干扰触发 CAN 控制器 Bus-Off 闭锁，系统在主循环中运行**纯非阻塞、分步解耦的异步自动恢复状态机**（`FDCAN_CheckAndRecoverAllBusOff()`）：
1. **捕获中断与标记**：在中断回调中捕获协议状态寄存器 PSR 的 BO 位，记录时间戳并置位软件标志；
2. **消抖等待**：等待 100ms 避开突发电磁噪声脉冲；
3. **状态机复位**：分步置位 `CCCR.INIT` 后清除，请求硬件重新初始化；
4. **监听隐性位序列**：硬件自动监听 129 次 11 个隐性位序列完成重同步并切回 `IDLE` 正常工作；
5. **双路总线隔离**：状态机严格隔离 FDCAN1 与 FDCAN2，单侧总线异常绝不阻塞主循环或影响另一侧总线。

## 五、单电池上电自检与联调验收步骤

在硬件板卡组装完毕、单动力电池接入后，请按照以下规范化步骤执行整机电气与通信验收：

### 5.1 板载指示灯自检与硬件状态确认

| 检查顺序 | 关注元件 | 正常现象 | 异常排查 |
| :---: | :--- | :--- | :--- |
| **Step 1** | **LED2 (PB1, 绿色)**<br/>系统心跳灯 | 上电后以 **1Hz 慢闪**（500ms 翻转一次） | 若以 **5Hz 极快闪烁**：表示存在 CAN1/2 Bus-Off 脱网，或电池 1 BMS 未收到唤醒回复/掉线。 |
| **Step 2** | **LED3 (PB2, 绿色)**<br/>动力就绪灯 | 1. 上电前 400ms 呈 **2Hz 闪烁**（预充缓启动中）；<br/>2. 预充完成立即切换为 **常亮**（动力已接通）；<br/>3. 蜂鸣器发出 90ms 短“滴”声。 | 若始终不常亮：检查电池 1 BMS 是否允许放电，或预充延时逻辑是否卡死。 |
| **Step 3** | **DCDC 输出** | 用万用表测量输出端子：<br/>- 12V 端子（小脑供电）应稳定输出约 12.0V；<br/>- 24V 端子（指示灯供电）应稳定输出约 24.0V。 | 若无输出：检查 PA7 (12V) 或 PC4 (24V) 是否被拉低使能。 |
| **Step 4** | **外部三色灯** | 上电自检完成后，外部指示灯默认点亮**绿灯常亮**。 | 若未点亮：排查 24V DCDC 供电或 PC2 吸电流驱动。 |

## 六、CAN 在线固件升级 (IAP)

本项目支持通过 CAN2 总线实现上位机小脑免拆机在线热刷写固件。

### 6.1 空间布局与架构设计

MCU 采用**单分区原地擦写（In-Place）+ 引导程序永久驻留**机制：

```
0x08000000 ┌──────────────────────────────────────────────┐
           │ Bootloader 分区 (20 KB, Page 0 ~ 4)          │ 永久驻留，CAN 驱动、Flash 擦写、安全接力
0x08005000 ├──────────────────────────────────────────────┤
           │ 元数据/标志区 (4 KB, Page 5)                 │ 记录魔数 0xA5A55A5A、固件大小与 CRC32
0x08006000 ├──────────────────────────────────────────────┤
           │                                              │
           │ App 业务固件分区 (104 KB, Page 6 ~ 31)       │ 存放电源板业务固件 (D-Y.bin)
           │                                              │
0x0801FFFF └──────────────────────────────────────────────┘
```

### 6.2 “无缝热接力 (Warm Handover)”防掉电机制

小脑 RK3588 的 12V 供电完全依赖电源板。若升级时执行冷复位断开 MOS，小脑将瞬间断电崩溃导致升级中断甚至变砖：
1. **热切入 Bootloader**：小脑下发升级指令后，App 关闭中断但**保持电池 1 主放电 MOS 及 12V/24V DCDC 持续使能**，使用软件平滑跳转（Direct Jump）交接控制权；
2. **Bootloader 接力维持**：Bootloader 初始化时快速接管引脚并维持供电，小脑在刷写 Flash 期间**不断电、不重启**；
3. **无感跳回 App**：升级校验成功后，Bootloader 写入热启动魔数并直接跳转回 App；App 启动时识别热启动标记，**跳过 400ms 预充延时和 MOS 关断时序**，零抖动接管供电。

### 6.3 上位机升级工具使用指南

上位机升级工具位于 [scripts/can_iap_tool.py](file:///home/yq/ghf/workspace/D-Y/scripts/can_iap_tool.py)，在 Linux 环境（RK3588 或调试工控机）下运行：

```sh
# 1. 确保 Linux CAN 接口已就绪 (250kbps)
sudo ip link set can0 down
sudo ip link set can0 type can bitrate 250000
sudo ip link set can0 up

# 2. 交互式控制台升级（推荐日常使用）
python3 scripts/can_iap_tool.py -c can0

# 3. 命令行一键自动热升级（适用于自动化脚本）
python3 scripts/can_iap_tool.py -c can0 -f build/Release/D-Y.bin --trigger
```

详细协议与升级实操手册请查阅 [CAN_IAP_GUIDE.md](file:///home/yq/ghf/workspace/D-Y/CAN_IAP_GUIDE.md)。
